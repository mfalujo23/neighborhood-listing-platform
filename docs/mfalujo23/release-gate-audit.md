# Michael Falujo — Production Release Gates

| Gate | Exact trigger and exit-zero condition | Blocking failure evidence and boundary |
|---|---|---|
| Production build | `npm run typecheck` and `npm run build`; static types and Next production compilation/prerender complete | Any nonzero exit stops CI and `verify:source`. Retain actual source-gates report; a local filesystem EPERM is a failed invocation, not a passed build. |
| Automated suite | `npm test`; every combined runner exits zero | `verify-all.mjs` stops on the first failed child. Raw suite assertions, commands, exits and durations are retained in `release-evidence/combined-tests.json`. |
| Migration integrity | `node scripts/verify-local-midterm.mjs` plus backend/sponsor/analytics runners inside `npm test`; fresh and supported compatibility scenarios apply and rerun safely | Invalid constraints, a failed migration, incorrect preserved rows or missing tables fails the runner. The guarded fresh bootstrap rejects existing tables with SQLSTATE55000/`FRESH_MIDTERM_PROJECT_REQUIRED`. Managed cloud application is pending and cannot be inferred from disposable PGlite. |
| RLS | Same database runners use anonymous/owner/other-owner/admin roles and exact row/error assertions | Unauthorized mutation must return SQLSTATE42501 or affect zero rows as specified; anonymous private booking reads return42501. An unexpected visible row or write fails `assert`. Protected fixture identities are local only. |
| Accessibility | Build the opt-in audit control, run real axe on rendered routes, retain its JSON, then `node scripts/verify-accessibility-evidence.mjs <report1.json> <report2.json>`; require valid axe metadata, positive executed-rule count, zero violations and zero incomplete checks | The actual command returns exit1 for the initial listings report (1violation), services report (1incomplete) and media report (1violation). `verify:release` also parses/hash-checks each accessibility artifact. Axe loading failures visibly alert. Component tests with mocked axe do not establish a rendered pass; final browser retest and keyboard review remain separate. |
| Core flow | Component tests cover service booking, listing filters, keyboard/focus and validation; root's observed browser traces cover actual rendered flows | Failed assertions or unsuccessful observed booking/filter/keyboard behavior block the gate. A fixture transport is not hosted Supabase. Five-person uncoached usability evidence remains a separate required human activity; no invented participants or interviews. |
| Deployment smoke | `node scripts/smoke-deployment.mjs --base https://<production-host> --commit <source-sha>`; home/health200, exact health source, approved narrow services200, anonymous admin401, legacy webhook410 and nosniff header | Any mismatch/nonzero status, timeout, stale commit, missing header, empty unseeded public service dataset or response-shape mismatch produces `passed:false` and exit1. `--application-only` cannot establish this gate. The liveness endpoint does not claim provider readiness. |
| Rollback | Owner configures and verifies Vercel's `vercel rollback <previous-production-deployment>` and `vercel rollback status`, then reruns full smoke for the previous source SHA | Hosted rollback is not configured or executed here. `monitorAndRollback` tests use a fake provider; failed candidate/recovery verification never passes a release. Actual traffic routing, authorization, eligible previous production deployment and successful post-rollback smoke are required before this gate passes. |

`npm run verify:source` is the real fail-fast source gate: strict lint, types, all local tests, production build. It performs no deployment. `.github/workflows/deploy.yml` enforces locked installation and the same core checks without tolerated failures, embedded credentials or deployment permissions.

`npm run verify:release -- --commit <40-character-sha>` requires all eight gate records at the same source SHA, evidence artifact hashes and hosted-scope smoke/rollback records. With no completed release record, the actual negative check returns **`RELEASE_BLOCKED: RELEASE_EVIDENCE_RECORD_REQUIRED`**, exit1. No passing release record, v0.5.0 tag or rollback receipt was fabricated. Unit fixtures demonstrating schema acceptance are clearly fictional and are not a real release approval. A recorded hash cannot establish that a human/provider claim is true; reviewers must inspect each artifact and its source.

Vercel rollback requires a deployment that previously served production. Hobby is limited to the immediately previous production deployment; rollback can restore old environment settings and disables automatic domain assignment until a later promote. Confirm actual account plan, immutable deployment source and safe schema compatibility before arming an automatic provider adapter. This repository has no cloud rollback credentials or enabled automatic traffic switch. [Vercel's documented constraints](https://vercel.com/docs/instant-rollback).

Lab8 release path: home → listings/filter/details → services/book receipt → eligible sponsor placement. Nonessential live voice/model integrations remain outside the local demonstration. Known blockers are actual managed database/Auth verification, all required rendered accessibility checks, main deployment and private-window smoke on the final commit, an approved hosted rollback drill, the five-person or approved substitute usability study, release tag, five-minute demo and personal retrospective. Do not substitute a successful build for these checks.
