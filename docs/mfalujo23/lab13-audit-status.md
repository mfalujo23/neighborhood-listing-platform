# Audit 13: empirical usability and traceable issue pipeline

Prepared material is available in `lab13-uat-plan.md`: an exact proposed consent script, three realtor tasks, three sponsor tasks, proposed measurable criteria, an additional live-telephony task plan, data handling and a traceability procedure. The observation CSV contains its header only.

The audit explicitly requires a live testing session of a deployed platform with a real consenting participant, one observed friction point, a live GitHub issue and a fixing feature-branch commit. Those requirements are not established by this work. No session, interview, recording, quote, approved stakeholder, observed frequency, live Twilio call, real SMS timing, issue URL or fixing commit is invented.

The local dashboard's default-off permission, deduplication, filters, revocation and safe failure can be exercised as a pilot candidate. Automated synthetic tests and browser automation are labeled engineering checks. They are not participant observations and cannot be substituted for the empirical traceability chain.

Required next evidence, after authorized deployment/setup: consent choices/reference; actual observation ID and timestamp; observed vs expected behavior; issue URL/number and allowed label; fix commit referencing the issue; repeat-task result; and the stakeholder/proxy disposition. Store no personal data in public notes. The course-required ChatGPT/Gemini/AI Studio observation grouping must use de-identified actual notes and preserve their IDs; no such session output is claimed here.
